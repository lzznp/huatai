## 0 这一场到底在解决什么（用户拍板的话）

> **"代码容易、生成效果也不错，就是精确交互困难。这个要是克服了，其他的设计类助手就通畅了。"**

所以本场的主题只有一个：**精确交互**。它被拆成两半，本场各拿到结论：

| 半边 | 一句话结论 |
|---|---|
| **改哪儿（范围）** | **"位置"能解决**（圈选 + 磁性吸附，已实测）；**"语义部位"（眉毛/眼睛/嘴唇）在现有条件下解决不了**——卡在**照片信号**与**模型能力**，不是算法 |
| **改多少（力度）** | **试算排可行**（一次给 3–4 张小图让用户挑），但用户明说**不是当务之急**：范围不清，力度给什么都白搭 |

**用户给的三条设计铁律**（下一场别违背）：
1. **不许要求用户先学一套符号、或先做一次"元操作"**（点开关、数格子、记编号）。九宫格被否的理由就是"太机械"；14 个中文位置词也被否——"还是换皮的格子"。
2. **范围优先于力度**。
3. 视觉打标签的初衷是**让不懂工艺的普通人能按名字说话**，不是炫技。

## 2 ★ 眉毛专项：为什么"以眉毛为例"现在做不到（本场最硬的实测）

用户举的例子是"**眉毛有点太密集了，把两个眉毛都处理一下**"。本场用**同一张真图**（`美女玻璃画\order-20261012-165706\src_one.jpeg`，400×380）试了两种"不用视觉模型"的做法：

| 做法 | 实测结果 |
|---|---|
| 上半脸里找"细长暗块"（暗于局部背景、横向连成条） | 找到的是**眼睛**（x 80–111/y 65–80、x 215–241/y 66–77）与**发丝**；**眉毛一个都没进榜** |
| 以"眼睛"为锚，在眼上方 8–34px 找最暗横条 | 找到的是**眉上额头 + 一缕刘海**（暗度 12.4 / 48.4 灰阶）——那个 48 的其实是**头发** |

**根因（要记住）**：**这张照片里的眉毛几乎没有信号**——被刘海盖住、与皮肤明暗接近。
- 区域生长要"特征与周围之差 ÷ 特征内部离散度 ≥ 0.6"才可能吸住；实测：**左眼 0.53、左眉 0.46**（`probe_edge_signal.py`）。
- ⇒ **不是算法差，是没有东西可找。** 在这张图上做"自动锁眉毛"，任何非识别类算法都会失败。

**顺带一个正面结果**：**眼睛能被稳定检测**（两次独立检测锁到同一位置，误差 **1–2px**）——所以"脸上有哪些成块的暗结构"这件事，不用视觉模型也能做。

**我（参谋长）当场犯的一个错，也记在这儿**：我先按"y≈10~16%"推断眉毛位置，实际那是**额头+刘海**；后来画了坐标尺（`exp-brow\坐标尺-眉毛到眼睛.png`）才纠正。**教训：谈坐标必须画出来对人眼，不能凭估计。**

## 3 ★ 视觉这条路：链路的每一步都通了，只差"模型有眼睛"

### 3.1 实测链（全部真跑）

| 环节 | 结果 |
|---|---|
| 运行时**认**图片块 `{"type":"image","mimeType":"image/png","data":<base64>}` | ✅ 认 |
| 0.1.2rc1 + `sdk-minimal` profile（**我们原来的配置**） | ✗ `SDK image prompt requires an attachment store`；代码里是 `no attachment store is mounted` |
| 查明原因（从运行时 exe 里读出原文） | 该 profile **没挂附件仓库**；官方 dsh 装配默认挂了（`@deepseek-ai/dsh-attachment` 的 README 原话：*"The shipped `dsh` composition enables this with no setup."*）；插件真名 `@deepseek-ai/dsh-attachment-local` |
| **升到 0.1.5rc1 + 完整 `sdk` profile** | ✅ 图片**真的存下来了**（`dsh_home\attachments\v1\objects\fa\fa2387…`，3465 B），调用 `finish=completed` |
| 让 agent 用 `read_image` 工具读文件 | ✗ **工具直接报错**：`model "deepseek-v4-flash" does not declare image input` |
| 试模型名 `deepseek-v4-vl` / `deepseek-vl2` | ✗ 服务端没有（`finish=error`） |

### 3.2 结论

**`deepseek-v4-flash` 是纯文本模型，不声明图像输入。** 其余每一环（SDK → profile → 附件仓库 → 图片投送 → `read_image` 工具）**都已经通了**。
⇒ 要用视觉，**必须换一条"有眼睛"的路**。

### 3.3 现成方案（外部调研，已有人趟过）

- [给 DeepSeek Harness 加一双「眼睛」：全局图片识别插件的完整实现与踩坑实录](https://juejin.cn/post/7673655608423235634)
  —— 同一痛点（作者用 `deepseek-v4-pro`，同样报 `does not declare image input`）。
  **方案：不换模型，把图片转成文字再藏进上下文**：
  host 插件调**阿里云百炼 Qwen-VL** → 用 `agent.inject()` 把识别结果作为**隐藏上下文**注入 → 用户正常提问时模型同一轮就"看到"了内容；输入框与消息全程不被污染。
  文内给了 **6 个真实坑的根因与修法**（客户端插件 `$mount` 是**异步**的、remote 必须 **strict codec（带 zod schema）**、远程代理是**位置传参**、能力判定默认值方向反了…），以及安装方式（host + client 双插件挂进 profile）。
- 第三方包 [dsh-vision-mix](https://www.npmjs.com/package/dsh-vision-mix)
- 官方讨论：[#5267 暴露每个模型的图像输入能力](https://github.com/deepseek-ai/deepseek-harness/discussions/5267) · [#112 接入第三方视觉模型说无法识别图片](https://github.com/deepseek-ai/deepseek-harness/discussions/112)

**用户已决定**：**去申请一个 key**（大概率阿里云百炼），拿到就试视觉。

### 3.4 拿到 key 之后怎么做（建议的最小实验，别一步做大）

1. **先验"模型能看图"**：拿本场自造的探针图（`tests\exp_vision_probe.py` 生成的"4 色块 + 大字『画台 7』"），直接调 Qwen-VL，看它能否说出**颜色位置**与**那个数字**。答对 ⇒ 视觉可用；
2. **再验"能不能定位五官"**：让它读**灰度预览**（不是点阵 BMP！），报出眉毛/眼睛/嘴唇的位置；
   **判据**：把它给的位置**画回图上**，看落点对不对（`exp_brow_detect*.py` 里已有画框的现成代码可复用）；
3. **最后才谈"注入上下文"**（那条路要写 host 插件，且要踩文章里那 6 个坑）。

**★ 一个已经验过的前提**：**喂给它的一定是灰度预览，不能是点阵 BMP**——我在 24.6% 墨点的点阵上（放大 3 倍）**只能看到左眼一点模糊痕迹，嘴完全看不出**（`exp-vision\C2-点阵放大3倍.png`）。**"上传那个做好的 BMP"这个想法是不行的。**
