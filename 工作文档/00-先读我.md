## 六 坑（新对话别重踩）

1. **工作区里的 exe 是 Low 完整性** → 判它要看**行为**（跑探针）；`Get-Acl -Audit` 在特权没启用时会**静默返回空**，不能据此下"没有标签"的结论。
2. **`proxy.golang.org` 本机不通** → 先设 `GOPROXY=https://goproxy.cn,direct`，否则任何 Go 依赖都拉不下来。
3. **别给原生命令接 `| Select-Object -First N`** → 管道提前关闭会把下载/构建**掐死**（同一天踩了**三次**：`go get`、`go build` 输出、`capabilities.py` 输出）。
4. **PowerShell 里别嵌中文引号** → 会被嚼掉、直接语法错（撞了一次）。一律单引号拼接，或写成 `.ps1` / `.py` 文件再跑。
5. `wails doctor` 的**真实退出码是 0**，但 PowerShell 会把它的 stderr 进度动画显示成 `NativeCommandError`——**别当成失败**；要判退出码就 `> $null 2> $null` 单独取 `$LASTEXITCODE`。
6. `Move-Item` **没有 `-Recurse` 参数**（写错过一次，导致壳没搬成、还嵌套了一层）。
7. **别在 PowerShell 里跑内联 Python**（同一天第二次踩）→ `r"D:\画台\kernel"` 被嚼成 `rD:\画台\kernel`，报错还指向别处。**一律写成 `.py` 文件再跑。**
8. **URL 里带中文必须百分号编码**（`urllib` 只吃 ASCII）→ 测试第一版就崩在这。界面/客户端同样要记得编码。
9. **测试抓出两个真问题，形状值得记**：① 工程名 `///` 被"静默改造成 `___`"——**静默变换比报错更坏**，改成拒绝（400）；② 服务端没问题，是**我的客户端**不会百分号编码。
10. **PowerShell 5.1，不是 7**：没有 `-Encoding utf8NoBOM`（那是 7 的写法）；写无 BOM 的 UTF-8 文件要用 `[System.IO.File]::WriteAllText($p, $s, (New-Object System.Text.UTF8Encoding($false)))`。
11. **PS 5.1 默认按 GBK 读文件** → 读 UTF-8 文件会读出乱码。**那是读法问题、不是数据问题**；要用 `[System.IO.File]::ReadAllText($p, [System.Text.Encoding]::UTF8)` 复核。
12. **`Start-Process` 带重定向时读不出退出码**（`WaitForExit()` 返回 True、`Get-Process` 也查不到进程，但 `.ExitCode` 是空的，`Refresh()` 也救不回来）⇒ **要判进程退出码就用 Python 的 `subprocess`**，别信 PowerShell 这条。
13. **第一帧可能带 BOM** → 别家工具写出来的 JSONL 第一行常有 BOM，不清掉就会被判成坏帧。`server\stdio.py` 已忽略 BOM，并**有常驻测试**（10.1）。
14. ★ **wails 模板的 `shell\.gitignore` 会忽略 `frontend/dist`** —— 模板假设它是 Vite 的**构建产物**；
    但本方案**不用 npm**，`frontend/dist` 就是**手写的前端源码** ⇒ 照模板配，**界面会一直不在版本库里**，
    回滚点也盖不住它（2026-10-12 发现并修复：已把 `frontend/dist` 纳入版本库，改为忽略 `build/bin` 与 `*.syso`）。
    **改前端之前先确认 `git status` 里看得到 `shell/frontend/dist/*`。**
15. **构建被中断会留下半成品**：`wails build -clean` 会先清掉 `build\bin`，若中途中断，那个目录就是空的
    （**运行位的 exe 不受影响**，还能用）。此时源码已改、exe 未更新 ⇒ **必须明确说一句"源码比 exe 新"**，别让人以为看到的就是最新的。

## 九 账的形状（已定稿，2026-10-12）

原则：**一单一个目录、只进不改、只追加**。**单 = 一张图 + 一段对话**（与内核一致：bestpic 决策 #7「每张图/每单活 = 一个 session_id」）；一个工程可以有很多单。

```
projects\<工程>\
    meta.json            工程身份：显示名 / 目录名 / 建项时间（★ 显示名 ≠ 目录名）
    <订单>\
        session.json     整单归档（版本链 / 指标 / 局部调整）
                         —— 直接用内核 orders.py 的格式，**不另立一套**
        src_<原名>       原图副本（★ 只进不改：进来之后任何代码都不许改写它）
        out\             每版产物：<stem>.png（预览）+ <stem>.bmp（1bit 上机档）
        transcript.jsonl 与小助手的对话流水（一行一回合，★ 只追加，不重写）
```
另有 `D:\画台\archive\`：打包 zip 保险档（内核的 `archive_dir()` 把保险档放在数据根的上级，免得被当工程扫描）。

**★ 对话流水必须"三分"**（参考包判据「流水三分」）：每行都带 `kind`，取值
`material`（壳塞进去的料）/ `user`（人说的话）/ `assistant`（小助手的话）/ `action`（结构化动作）/ `system`（系统事件）。
**人和机器的话不许混成一行**——否则聊天区会掺满内部日志，最难看也最难看懂。

## 十 第 4a 步：大脑接线（只读往返，已验）

**做法**：`server\brain.py` —— 把"跟大模型说一句话、拿回 JSON"封装成一个动作，**不接任何业务**。
四条纪律：

| 纪律 | 为什么 |
|---|---|
| **懒启动** | 第一次问它才拉起运行时；只问状态不花钱、不联网 |
| **串行**（一次一回合） | SDK 不支持并发 `run`；并发会乱 |
| **`cwd` 收窄到空目录** `D:\画台\.agent-cwd` | agent 少看见点东西，就少一点乱来的机会 |
| **密钥只留一处** | 从项目根 `.env` 读；**不复制到 `kernel\`**（一份秘密一个地方） |

**★ 顺手补了老项目欠的 `FIX-2`**：`agent_bridge.py` 原来把 `finish_reason` 和用量**丢了**，
于是"被截断"和"没给出 JSON"在界面上长得一模一样。现在 `AgentReply` 带
`finish_reason` / `usage` / `elapsed_ms`，并有 `truncated` 属性；**截断时错误文字里明说被截断**。

**实测（真机，两次）**：

| 走法 | 结果 |
|---|---|
| Python 直跑（冷启动） | `completed`、未截断、**5813 ms**、input 1260 / cacheRead 0 / output 30 / reasoning 15 / **total 1290** |
| **走 Go 壳** `画台.exe --with-brain --selfcheck` | `completed`、未截断、**2000 ms**、**total 1361**、自检 **31/31** |

**用量口径**（跟着数字走，别只报总数）：`totalTokens = inputTokens + cacheReadTokens + outputTokens`；
`reasoningTokens` 是 `outputTokens` 的**子集**，**不相加**；`inputTokens` 不含缓存读。

**判据**：
- 离线（不花钱）`tests\test_brain_offline.py` **27/27**：抠 JSON 四种形状、抠不到要抛错、
  用量口径、截断识别、`reply_to_dict` 带齐观测字段、懒启动、密钥就位。
- 真机（**花钱**）`tests\smoke_brain.py`：手工跑，验"运行时起得来 + 拿回合法 JSON + 结束原因与用量如实回来 + 会话可追"。
- **花钱的那条不进默认自检**：`--selfcheck` 默认 **27/27**（全免费）；加 `--with-brain` 才做真机往返（**31/31**）。

**坑（本段新增）**：
- **PowerShell 5.1 的 `*>` 重定向写出的是 UTF-16**（带 BOM）⇒ 我自己的日志工具按 UTF-8 读会当成二进制。要写可读日志得用 `[System.IO.File]::WriteAllText`。
- **投递 exe 之前必须先关掉正在跑的窗口**：exe 被占用，`Copy-Item` 会失败（本段踩到，害得自检跑的是旧程序）。

## 十一 第 4b 步：猜意图（已验），界面已接通

**用户没说要做什么时，小助手的职责是"搞清楚他要什么"**：先猜 → 拿不准就问 → 要的东西做不到就**当场明说**。

**做法**：`server\intent.py`（要点卡 + 校验器 + 落账）+ `capabilities.render_for_prompt()`（把能力声明渲染进提示词）。
界面：投料按钮（走 Wails 的系统选图对话框）→ 建单 → 对话区（按 kind 分色）→ 说一句话 → 小助手的回答。

**三条设计纪律**：

| 纪律 | 为什么 |
|---|---|
| **能力清单从同一份代码渲染** | 绝不在提示词里手写第二份清单——手写必漂，漂了就是"假装生效" |
| **上下文封顶**（只带最近 6 轮、每轮截 200 字） | 参考包判据 8：会话无限堆积 ⇒ 输入量随对话变长没有上限 |
| **它说的话要过校验器** | 工艺 id 不在清单里 / action 不认识 / `ask` 却没 `question` ⇒ **整轮作废并记账** |

### ★ 真机实测（三轮，合计 8804 token）

| 轮 | 给它什么 | 它怎么回 |
|---|---|---|
| 1 | **什么都没说**，只投了一张图 | 「**我猜你可能是想做玻璃画，对吗？**如果你是想做叶雕或剪纸·只雕不切穿，也请告诉我」＋「我先确认工艺，**不贸然开工**」 |
| 2 | 「做成玻璃画」 | 给出下一步：灰度 → 明暗/反差/细节/素描 → 3×3 局部 → Floyd–Steinberg 仿色 → 预览＋上机档＋指标 |
| 3 | ★★ **同一句话**，只把清单里"玻璃画"翻成做不到 | 「玻璃画这一版**确实做不了**……要不要改走叶雕或剪纸·只雕不切穿？」 |

★ 第 3 轮是**硬骨头判据**：同一句话、同一个模型，**只改了清单一处**，它就改口了
⇒ 证明它是在**读清单**，不是在背台词。（它还把钩子的说明文字逐字念了出来——这是额外证据。）

### 判据总账

## 十二 第 4c 步：出图（已验）—— 它现在**会干活了**

**人话 → 参数 → 确定性出图 → 反馈 → 局部调整 → 再出图**，整条闭环第一次走通。

**做法**：`server\render.py`（校验 → 调 `pipeline` → **独立回读** → 落账）+ `intent.round` 里多了一支：
小助手这一轮可以 `action="render"`，**它只给参数，图由管线算**。

### ★ 三条硬设计（都来自老项目踩过的坑）

| 设计 | 为什么 |
|---|---|
| **旋钮是"累积状态"**，不是"某次回复的残影" | 你说"背景白一点"，它只写那一个旋钮；若按默认值重建，**你之前调好的素描感就被静默归零**。现在只覆盖它明确写出的那几个（上一版的值从 `last_report.knobs_applied` 读回） |
| **独立回读**：从 BMP 反算黑点占比 | 同一个函数既改图又算分，那叫"同源自证"。从产物反算才是证据；对不上直接报错，不静默 |
| **缺口旋钮必须喊出来** | `背景纯净度/脸部提亮/疏密细腻度` 名字合法但没接线。写了不生效 = "假装生效"，所以返回值、账、文字三处都留痕 |

### 真机实测（三轮，合计 11045 token）

| 轮 | 用户 | 它 |
|---|---|---|
| 1 | （只投了料，没说话） | `action=ask`：「我猜你是想做玻璃画，是吗？」 |
| 2 | 「做个玻璃画」 | `action=render`，`{素描感强度: 0.7}`（**守住"空泛要求给 0.5~0.8"的工艺默认底**）→ **出图 v1**，墨点 18.0%，PNG+BMP 落盘，回读与自报一致 |
| 3 | 「左上角太暗了，提亮一点」 | `action=render`，`local=[{zone:0, op:brighten, amount:0.3}]` → **出图 v2**，墨点 18.0%→17.5% |

### ★ 附带产出：一条"能力清单是否诚实"的自动判据

`tests\test_knobs_effect.py`：**每个标「已实现」的旋钮必须真的改变产物；每个标「缺口」的必须一动不动**。
——"缺口"这三个字从此不是嘴上说的，是**跑出来的**。

> ⚠️ 一个必须记住的坑：测"细节保留度"**要用有高频细节的图**。拿平滑渐变去测它会得到"这个旋钮坏了"的**假结论**
> （USM 的 threshold 对平滑渐变本来就不起作用）。本文件建立当天先踩了这个坑，靠探针查清的。
