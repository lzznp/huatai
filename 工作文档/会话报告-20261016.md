## 2 ★ 智能笔刷：本场的主要工程成果

### 2.1 它是什么（用户提的想法，两条都采纳）

> 用户原话精神：① "我手动操作时是在**灰度图**上用**减淡工具**，操作以后再存位图再看效果，**很不方便**。
> 如果有个**智能笔刷，直接操作位图**呢？"
> ② ★ "这个智能笔刷**能否控制使用者的坏习惯**？万一刷到不该刷的地方了，**能不响应**，或者小助手能提醒他？"

**⇒ 第②条是人机协同的新维度：从"助手挡错"扩到"助手帮用户守住规矩"。**

### 2.2 ★★ 四条护栏（代码保证，不是靠用户注意）——**本场最值钱的部分**

| 护栏 | 保证 | 实测口径（真上机档 787×748、墨点 24.0%） |
|---|---|---|
| **0 密度闸门** | 只删"明显比全图密"的点；低于闸门一律不碰。默认 = 全图黑点密度的**第 70 百分位**（阈值 **40.4%**） | 脸颊(120,160)横扫：扫过 5885 点，**泄漏率 2.96%**（基本刷不动） |
| **1 只删不补** | 稀疏模式**绝不新增任何点** ⇒ 背景（白点）物理上不会被涂黑 | 任何位置刷 ⇒ 新增 **0** 个 |
| **2 不越界** | 一次涂抹只动笔刷圆内 | 圆外改动 **0** 点 |
| **3 没东西可改就明说** | 被闸门挡住时**当场告诉用户**，并说"想改把闸门拉低" | — |

**为什么护栏0是必需的（实测逼出来的）：**
```
脸颊 黑点 22.5%   鼻梁 24.9%   额头 18.4%
全图最密处(右下深色衣服 约(620,300)) 88.2%
```
⇒ **脸本身就有 22~25% 的黑点**，光靠"只删不补"拦不住，会把脸也刷稀。

**附带产出：可调闸门** —— 用户仍能强制（把闸门拉低即可），但**必须自己动手**，这就是"控制坏习惯"的落点。

### 2.3 判据（`tests\exp_smart_brush.py --selftest`，**7 项全绿**）

```
脸颊泄漏率 2.96%（<10%） / 脸颊确有 19% 的点被闸门挡下
极稀处(330,250)刷：删 0 个
密区(640,330)刷：删 2499 个
稀疏模式任何位置：新增 0 个
笔刷圆外：改动 0 个
撤销一笔：精确回到基线
1bit 成品与内部点阵逐像素一致（没混进标记色）
```

### 2.4 ★ 用户实测暴露的三个 bug（**都由用户发现，已修**）

| # | Bug | 用户怎么说的 | 根因 | 修法 |
|---|---|---|---|---|
| **1** | **粉色标记盖住成品** | "现在是修改的部分是粉红色了，这个也**看不出来效果**啊" | 我把"被删的点"涂成实心粉直接叠在成品上 | 成品默认**干净黑白**；标记改成可选覆盖层 |
| **2** | **拖动时重复扣点 ⇒ 把纹理刷没** | （由导出 JSON 发现）一笔有 **359 个印子** | 每个印子都按预算删一遍，重叠处重复扣 | 预算改成按**笔刷扫过的唯一点**算 |
| **3** | ★★ **按"最密"删 ⇒ 挖洞而不是变稀** | "**破坏了一画面的连贯性，类似一块一块儿那种感觉**" | 按密度排序删最密的 55% ⇒ 把最密区**整块挖掉** | 换成 **Bayer 8×8 有序抖动**选删哪些 ⇒ 空间上均匀 |

**★ 第 3 条是本场最重要的"认识"**：**"变稀"是"均匀地各删一点"（印刷网点的道理），不是"挖掉最密的区域"。**

### 2.5 ★★ 用户对方向的判断（本场最关键的取舍）

用户 2026-10-16 原话精神：
> "导出了，但感觉**力度有点过大**……**类似一块一块儿那种感觉**。
>  我**隐约感觉这个路子好像是比较对的**，我们再讨论讨论。"

**参谋长给的诊断（用户认可）：**

| | 现在的做法（减法） | 应该的做法（目标） |
|---|---|---|
| 每刷一次 | 再删掉一片，不管现在多稀 | **朝一个目标浓度去改，到了就停** |
| 同一块刷 3 遍 | 删 3 次 ⇒ **越刷越白、直到挖空** | 达标后**不再动** |
| 深/浅的地方 | 删掉一样多 ⇒ **深浅被压平** | 深的多删、浅的少删 ⇒ **浓淡关系保留** |
| 观感 | **一块一块**（刷过的地方断掉） | **整体变淡**（过渡还在） |

**⇒ 这正是用户当年用 PS 减淡工具的道理：减淡压的是"暗度"，不是"删黑点"。**

**B 的实现前提已经做完**（在 `exp_interactive_snap2.py` 里，可复用）：
